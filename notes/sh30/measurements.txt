Item 1: fish 4.9.3, measured through an owned pty on hasu B (CPUs 6-11)

36 fresh-HOME sessions: all 12 cases under each of xterm-256color, linux,
and dumb. fish-probe.py records hex bytes before/after each typed step,
SGR subsequences, and fish's public set --show / commandline outputs.
No implementation source read. These are the shipped default theme, not
colours recollected from another fish version. Raw evidence: fish/*.json.

Settled text palette; xterm-256color and linux agree:
  resolved command and reserved word: default/reset foreground (39)
  unresolved command: bright red (91), including the unfinished e/ec/ech
  closed quote: yellow (33)
  unclosed quote: opening delimiter bright red (91), body yellow (33)
  variable: bright cyan (96), including inside a double quote
  redirection operator and target: cyan + bold (36;1), reset ESC[m
  comment: red (31)
  pipe and command separator: green (32), fish_color_end, NOT fish_color_operator
  argument: cyan (36), fish_color_param
  shadow: bright black (90), reset foreground (39)
  syntax error token ')': bright red (91)
  Enter: fish emits the diagnostic/echoed line/caret without SGR; the retained
    edit line is redrawn with ')' bright red. Pelt's coloured caret is therefore
    a requested pelt behavior, not measured fish parity.
  TERM=dumb: no SGR in any measured typed step, including Enter error.

Fish initially echoes using a preceding style, then asynchronously repaints;
raw recordings retain both. Palette claims above refer to the settled line.
For echo, red e/ec/ech repaints to default when the o resolves the command.
A lone ! is default (fish negation); !! is bright red. F2's explicit contract
keeps leading ! literal as an ordinary word, not fish's negation classification.
