# Speed — pelt against dash (sh06, item 4)

Host: kasumi (x86_64, 16 cpus, CachyOS, kernel 7.2.8). dash 0.5.13.4-1.1
(`/usr/bin/dash`, sha256 `c6221703…`). pelt at `4437c81` (trunk `b32bebc`
code), built from the 0.2.27 / 0.1.50 archives by digest:
`release` = `~/lanes/sh06/pelt/target/release/pelt` (LLVM, the shipped
tier), `native` = `target/native/pelt` (the default backend).

Method: `bench/run` (python3) runs each script 9 times per shell, each in
a fresh scratch directory from `env -i PATH=/usr/bin:/bin HOME=… LC_ALL=C`;
wall from a monotonic clock around the process, user/sys from its `wait4`
rusage (children included); median and min of wall; standard output must
be the same bytes under every shell or the row is refused (none was).
Ratio is median ÷ dash's median. The four scripts are this lane's own
writing (`bench/fork.sh`, `pipeline.sh`, `param.sh`,
`configure-shaped.sh` generated by `bench/gen-configure-shaped 1200`).

Commands (kasumi, `cd ~/lanes/sh06/sc`):

```
python3 bench/run --dir ~/lanes/sh06/sc/bw --runs 9 dash=/usr/bin/dash \
    pelt=$PEL/release/pelt native=$PEL/native/pelt
python3 bench/run --dir ~/lanes/sh06/sc/bw --runs 9 --pin 0-3 dash=/usr/bin/dash \
    pelt=$PEL/release/pelt native=$PEL/native/pelt
```

## Where the time goes

**The worst ratio is `param` (3.9× release, 10.2–10.6× native)**: no
program runs, so it is the shell's own cost per simple command.

- `perf stat -e instructions:u,cycles:u` (perf is permitted on kasumi,
  `perf_event_paranoid` 2, own processes): pelt release **20.18 G
  instructions, 7.06 G cycles, 1.52 s** against dash's **5.19 G, 1.68 G,
  0.357 s**. Per loop turn (200,000 turns, ~8 simple commands and
  expansions each): pelt **~101,000 instructions, ~7.2 µs**; dash
  **~26,000, ~1.8 µs**. IPC is similar (2.86 vs 3.09): pelt does ~3.9×
  the work, it does not stall more.
- `strace -c -f`: the loop makes 592 `brk` and nothing else of note —
  **the time is not in system calls** (sys 0.023 s of 1.45 s).
- `perf record -e cycles:u` + `perf report --sort symbol` (top of
  pelt's own code, 91.8% in the binary, 8.0% in libc):
  `__wolf_rt_list_new` 8.4%, `sh.run_fast` 8.1%, `__wolf_rt_list_push`
  6.2%, `sh.xw` 5.7%, `sh.putb` 5.2%, `sh.binary` 4.4%, `sh.eat` 4.1%,
  `__wolf_rt_map_get` 3.6%, the runtime's ambient-region lookup
  (`AMBIENT_REGION` closure) 2.9%, `wolf_rt::list::alloc_in` 2.5%,
  `region_alloc_slow` 2.2%, `sh.ws` 2.0%, `core::str::from_utf8` 2.0%,
  `__wolf_rt_str_from_utf8` 1.7%, `__wolf_rt_map_new` 1.7%,
  `__wolf_rt_map_copy` 1.0%, `list_from_bytes` 0.6%. **Allocating,
  growing and re-validating lists, maps and strings is ~29%** of cycles
  (the runtime symbols summed); the libc share (unsymbolised, at
  `0x1afd00…`, inferred to be `memcpy`/`memmove` from its address
  cluster, not verified) adds ~4%. The rest is pelt's own interpreter:
  arithmetic (`binary`, `eat`, `level_ops`, `primary`, `parse_const`)
  is parsed from text on every turn, and every command builds its byte
  output through `putb`.
- **The native tier is 2.6× slower than release on this loop** (3.77 s
  vs 1.45 s), and within 3–15% elsewhere: a shell whose cost is its
  own interpreter loop pays for the default backend; scripts that run
  programs do not.

**Fork- and pipeline-shaped work (1.4–1.7×)** is spawn cost:
`strace -f -c` on `fork.sh` — dash: 2,000 `vfork` + 2,001 `execve`,
68,074 syscalls total; pelt: 2,000 `clone` + 2,001 `execve` +
**2,000 `socketpair`, 12,000 `fcntl`, 22,005 `close`, 6,000
`rt_sigprocmask`, 2,000 `recvfrom`**, 114,060 total (57 per spawn
against dash's 34). `clone` costs 21 µs against `vfork`'s 9 µs (strace
times, inflated by tracing): the spawn is a full-copy clone with an
exec-error side channel (socketpair + recvfrom) and a close sweep of
descriptors, where dash's `vfork` shares the address space until exec.
`configure-shaped.sh`: dash makes 1,603 `clone` + 403 `vfork` (it
forks for subshells and substitutions of built-ins), pelt 1,005
`clone` (it runs those in-process), yet pelt is still 1.5× slower
because each of its spawns costs ~78 µs of `clone` and ~45 µs of
`execve` under strace against dash's 13 µs and 5 µs, and pelt makes
8,432 `statx` (7,025 failing; inferred, not traced per call: a PATH
search per command that a `hash` table would cache — dash's summary has
no `statx` row).

## Reading for the plan

- Scripts that run programs: pelt is ~1.5× dash today; the lever is the
  spawn path (a `vfork`/`posix_spawn`-shaped spawn in wolf-lang's
  runtime, no per-spawn socketpair, no close sweep when the fd map is
  explicit) and a command hash table in pelt.
- Scripts that loop in the shell: ~4× on release, ~10× on native; the
  lever is pelt's own allocation per command (lists and maps built and
  dropped per word), arithmetic parsed once, and output buffered once —
  pelt's work, no upstream need, measured by `bench/param.sh`.
